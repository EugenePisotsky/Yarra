Current implementation; gameplay foundations simplified September 30, 2026. Use [workflows](WORKFLOWS.md) to operate the tools, [performance](PERFORMANCE.md) to measure them, [experiments](EXPERIMENTS.md) for decisions/results, and [refactoring](REFACTORING.md) for remaining structural work.

Game launch options are parsed once in `app_game/launch.rs` and injected as resources/settings. Shared runtime/rendering libraries do not inspect process arguments or bind experimental keys. [RuntimeSettingsPlugin](../crates/app_game/src/runtime_settings.rs) owns the shared render/feature snapshot and applies it to cameras, materials, atmosphere, vegetation and input. It initializes before output setup and before F1 captures its reset baseline. [PerformancePanelPlugin](../crates/app_game/src/render_audit.rs) composes the optional controls, UI and capture session; game startup and [reproduction routes](../crates/app_game/src/repro.rs) work without it. Diagnostic overrides remain fields of the shared snapshot so CLI/F1/reset/A/B use the same state.

Within [performance diagnostics](../crates/app_game/src/render_audit/performance.rs), `panel` owns layout/input/visibility, `capture` owns launch/reset snapshots and bounded A/B recordings, `telemetry` owns frame/app history and pipeline readiness, and `report` owns statistics, comparison text and CSV export. Capture completion returns an outcome to presentation; the recording session has no UI entities or panel visibility state.

`--diagnostics off|panel|full` controls composition. Full preserves the previous default. Panel installs F1 and frame/app cadence collection without CPU system wrappers or GPU probes; Off omits both panel and timing plugins. The vegetation renderer no longer installs Bevy's diagnostics recorder itself; game/editor composition chooses it explicitly. Renderer workload bookkeeping remains part of rendering, and explicit repro/profile automation still works in Off mode. F1 captures canopy values, terrain macro variation and page gizmos alongside other settings.

Keep data/compiler crates independent of Bevy. Renderers do not own SQLite or editor workflows. Currently `engine` depends on both renderers, atmosphere and `world_db`; `world_db` includes authoring/compiler dependencies; vegetation rendering depends on upscaling for temporal integration. These are real dependencies, not a fully separated gameplay/runtime architecture yet.

```text
content/world.project.sqlite
  → bounded source snapshot + environment compilation + world cooking
  → staged, validated runtime publication
  → assets/generated/world.runtime.sqlite
  → read-only database worker → asynchronous decode
  → bounded attachment/removal → renderers and gameplay consumers
```

The editor overlays unsaved source edits on the published runtime. Save changes source; publication creates a new immutable generation. Failed publication leaves the previous generation usable. Runtime pages are derived products, not authoring state.

## World, source and persistence contracts

[world_db](../crates/world_db/src/lib.rs) keeps its public API at the crate root. `records` defines data contracts; `project` separates bounded editor reads/writes from whole-document import/export; `runtime` separates immutable reading from whole-build/incremental output writes. `catalog`, `page`, `storage`, `limits` and `error` own shared encoding, validation and budgets. `cook_store` owns only the bounded source snapshot. Existing environment, road, atmosphere and terrain stores retain their domain transactions and queries. These are internal modules; runtime-only dependency packaging remains future work.

- Stable IDs identify worlds, definitions, assets, placements, presets, layers and roads. Visual entities are disposable representations of those identities.
- Logical positions use world/cell coordinates; render transforms are relative to a floating origin. Rebasing must preserve world-aligned texture, wind and canopy phase.
- `init` creates the Phase 0 [island](../crates/world_cook/src/island_fixture.rs): a ~28 km² island with a 745 m massif, centred in an 8,192 m square of sea. [Imported heightfields](../crates/world_cook/src/heightfield_import.rs) build the same kind of world from a terrain tool's export ([terrain_world](../crates/world_cook/src/terrain_world.rs) holds what they share). Both use 32 m cells with 1 m heights and 1 m paint, a sea level and composite minimum level 2. Exactly flat cells (open sea) store neither heights nor paint. A world may record a start view (project settings, copied to runtime metadata outside the content hash); without `--start-view` the game adopts it when the runtime opens and moves the player and camera there, and the editor focuses it. An import writes cells in place ([terrain_import](../crates/world_db/src/terrain_import.rs)), advancing revisions only where heights or imported coverage changed and never deleting a paint revision, so re-imports cook incrementally. A layer with an `imported_mask` takes its coverage from the import's mask of that name, or else from the masks generated from height and slope (`land`, `green`, `bare`, read by the three meadow layers); imports rewrite only those layers and keep painted ones, and the editor does not paint them. Imported coverage fades out over the world's last 48 m because the cook requires neighbouring cells to agree along shared edges, including the empty ones beyond the world. The small 8 m authoring world is `create-road-demo`. Cell size is per world; `DEFAULT_CELL_SIZE = 32` is not proof that every world uses that grid.
- Current versions: source **28**, runtime **26**, page payload **9**, terrain node **2**, recovery journal **15** (reader accepts journal 12–15). Source/runtime constants live in [world](../crates/world/src/lib.rs); journal versions in [journal](../crates/app_editor/src/journal.rs). Incompatible source formats are rejected, not silently reset.
- Editor reads/writes are bounded and revision-checked. Undo/redo uses stable-ID commands. Save commits coherent revisions; stale writes report conflicts. Recovery is separate from ordinary save.
- Production cooking uses one consistent source snapshot, bounded cell/halo batches and staged output. Cell compilation and the material bake's leaf cores, parent cores and finished tiles run on every core in fixed batches ([parallel](../crates/world_cook/src/parallel.rs)). Inputs are read and results written on the cook thread in key order, so the publication is byte-identical to a sequential cook. `cook` prints phase times. Whole-document helpers remain fixture/parity references and share compilation code with production.
- `cook` continues the previous publication when its global inputs (the header hash over catalogs, profiles and environments) and its set of terrain cells are unchanged. It clones the runtime (copy-on-write on APFS) and recompiles only cells whose input fingerprint changed: the cell's source, its 3×3 halo of heights, paint and roads, and its placed objects. Only cells whose ground page changed replace their terrain leaf and its ancestors; a change of the world's hierarchy grid resolution replaces every node in place. Composites re-bake only cores with a changed cell beneath and re-finish only tiles whose 3×3 neighbourhood holds a core that changed. Clean cores come from the cook cache by the fingerprints the runtime records in `terrain_cores`. A clean core missing from the cache, or a different bake library, bakes that space afresh. `cook --full` rebuilds everything. Tests check that both paths publish identical content hashes.
- Unloaded source is unknown, not empty. Road/coverage queries must certify sufficient bounds/halos before compilation.
- Schema or bincode enum changes require explicit version/recook decisions. The old `TerrainRender` payload is still readable, while current cooking emits `TerrainHeightfield`; deleting its enum variant casually would shift serialized discriminants.

## Standalone gameplay foundations

The gameplay libraries run without Bevy, game/editor startup, cooked worlds or art assets. The game uses them only in the opt-in `--story` slice; the editor does not depend on them. [The content CLI](../crates/game_content/src/main.rs) exercises inventory, trading, equipment, dialogue, quests, world triggers, Fluent and save/load together; [workflows](WORKFLOWS.md#standalone-gameplay-and-saves) has the commands. [The roadmap](REFACTORING.md#gameplay-roadmap) lists what changes next: several of the models below (dialogue graphs, triggers, character rules) are about to be replaced.

```text
game_types (IDs, keys, text references, logical time)
    ↑ gameplay (rules, actors, inventory, quests, dialogue, world, session)
    ↑ save (snapshot files)          localization → game_types + Fluent
    ↑ scripting (Luau engine behind gameplay's script trait)
    ↑ game_content (RON/Fluent/Luau → SQLite, runtime reader, tools)

engine/apps (future): compose session, saves and localization with Bevy/UI
```

`gameplay` contains the domain modules that used to be separate crates. They stay separated as modules: `rules`, `inventory`, `actors`, `quests` and `dialogue` hold data and pure operations; `session` coordinates them. No domain imports Fluent or stores rendered text.

### State in memory, content on demand

Two decisions shape the runtime:

- **The whole mutable playthrough is in memory** ([`SessionState`](../crates/gameplay/src/state.rs)): actors, inventories, wallets, quests, relationships, dialogue history, conversations, object/location/trigger state, pending events, variables, clock and random streams. Records are keyed maps. A record that was never changed is absent and reads as its default (an unstarted quest, a neutral relationship, an object in its authored state), so state and saves contain only what differs from the authored world. Quests, triggers and scripts can ask about any actor at any time; there is no "not loaded" state to handle.
- **Content is split by how it is used.** Definitions that commands consult constantly are loaded once when a session opens: rules, item catalog, actor templates, scripts, quests, interaction profiles, named predicates, dialogue *contracts* (roles, line/choice IDs, repeat policy), objects, areas and triggers. Dialogue graphs are read when something first needs one (a command or a read model asking `content.dialogue(id)`) and kept in a small least-recently-used cache (`MAX_LOADED_DIALOGUES`, 32); the session hands its source to the content for this ([`graphs.rs`](../crates/gameplay/src/graphs.rs)). A graph that cannot be read fails what needed it, as any other error would. Text contracts and wording are never loaded by a session; the formatter asks for them.

[`ContentSource`](../crates/gameplay/src/runtime.rs) is the one port: `identity`, `core` and `dialogue(id)`. `ContentRepository` implements it over a published bundle; `ToolContent` implements it over a complete in-memory project for tests and authoring tools.

### Commands

[`GameSession::apply`](../crates/gameplay/src/session.rs) accepts a command as a whole or leaves state, clock and both random streams untouched. It runs the command against a [`Tx`](../crates/gameplay/src/tx.rs): every write first remembers the record it replaces. A rejected command is undone from that journal; an accepted one uses it to

- in debug builds, re-check the records it wrote (plus actors whose equipment depends on a changed inventory), which only finds mistakes in the rules' own code; release builds leave it out;
- derive notifications (item acquired, quest changed, area entered…) and queue those a trigger subscribes to.

New items take identities from the inventory that makes them: its own identity and how many entries it has made before, a count kept in the inventory record. A replay after loading makes the same items, and an undone command gives the numbers back with the rest of the record.

The queued work is then carried out before `apply` returns, one piece per step, each a transaction of its own, so a command's outcome is settled state.

Cost therefore follows the records a command touches, not the size of the playthrough: three item commands against 20,000 actors take about 0.1 ms in the dev profile. Nested scopes (`savepoint`/`rollback_to`) let a failed trigger plan be undone on its own while the rest of the command is kept. The full-state check runs when a playthrough is created or loaded.

Read models (`state()`, `derived`, `conversation_view`, `preview_interaction`, `quote_trade`, `container_contents`, `next_movement`) never consume randomness. [`Driver`](../crates/gameplay/src/driver.rs) wraps the same commands with a fixed time step for the game and headless runs alike, an optional event trace and `advance_until`.

### Content and publication

[The checked-in project](../content/gameplay/demo/project.ron) is authored as RON plus Fluent: a project lists package directories; a package's files say by their names what they hold (catalog fragments, actor templates, rules, quests, profiles, predicates, world objects and triggers, conversation graphs, scripts), its `package.ron` declares its areas and variables, and its Fluent files are its one text resource. Names such as `guard/gate`, not paths or package order, are identities; a name hashes to the 16-byte identity used at runtime. RON and Fluent are the only authoring source; gameplay reads published SQLite only.

`LoadedProject::build` publishes one immutable bundle (schema **12**): one checksummed JSON record per asset keyed by `(kind, id)`, a manifest with the mechanical fingerprint, and a tool-only scenario. `ContentRepository::open` reads the manifest; `read`/`read_kind` verify checksum and identity of what they return. Language packs (schema **1**) are published separately per locale, so wording fixes need no mechanical rebuild and do not affect saves. The mechanical fingerprint covers definitions, rules and world binding and excludes translations.

Conditions and actions are closed enums in [`content.rs`](../crates/gameplay/src/content.rs), shared by dialogue choices, interaction profiles and triggers, with `All`/`Any`/`Not` and named predicates. They are written inline where they are used. `Script("module.function")` is one more variant of each, run by the Luau engine the content carries; see [the roadmap](REFACTORING.md#step-4-done) for the script rules.

### Saves

A [save](../crates/save/src/slots.rs) is one file per slot: a one-line header (format, slot info, content identity) followed by the state as JSON. Listing slots reads only headers. Saving writes a sibling file, syncs it and renames it over the slot, so a failed save leaves the previous one intact. Loading does not require the content the slot was saved with. It brings the state in line with the content at hand (every character's stats worked out again with the current formulas, resources kept within their caps, party members raised to the level the party's experience now earns), then checks the whole state against it and refuses, with the reason, what still does not fit. The header's content identity lets the game tell the player the content has changed. Save format **16**; other formats are rejected, not migrated. `ContentLibrary` retains published bundles by fingerprint so a slot can also be restored against the exact content it was saved with.

Changes the load cannot account for (a removed item, class or quest the save refers to, a new primary stat) refuse the save. That is enough while worlds and saves are disposable; a shipped game patching content under existing saves would need more.

### Current domain behaviour

These work today and are covered by the headless scenarios and tests.

- **Dialogue:** a flat graph of nodes, each with a speaker role, text, an inline condition and actions, and ordered children. After a node the first eligible child decides: a line plays, or the eligible choices are offered. Roles are required, optional or a named character who joins when in the party, so companion reactions, lines for particular combinations of companions and NPC replies to them are ordinary nodes. Runs are keyed by `(dialogue, participant, speaker)` and keep a cursor token; explicit repeat policies and scoped history carry over between runs, and variables remember rewards given.
- **NPC interaction:** a profile's prioritized entry rules pick an opening, offer independent topics and choose weighted variants from a separate narrative random stream.
- **World:** object lock/open/destroyed overlays; areas known by name; triggers that listen for signals (entering or leaving an area, a walk arriving or failing, an item acquired, a quest, variable or dialogue change) and run their actions as a unit; walks requested by `Move` and completed when the engine reports the actor inside the area. Dialogues are blocking or ambient.
- **Characters:** stats declared by the rules as primary, derived or a resource; derived stats and skill checks are functions in the rules script, and a character's stats are stored and worked out again only when what it is built of changes. Classes grant points and abilities per level and cap what trainers teach; experience and gold belong to the party. Status effects carry modifiers and periodic changes.
- **Actions in time:** abilities with durations, costs and cooldowns; each character has a queue of intents, begun one at a time and resolved by the ability's script. No turns: passing time visits only characters with something pending.
- **Inventory:** stacks, transfers, wallets and fixed-price trades with stale-quote detection. NPC and container inventories are made from loot tables the first time a command needs them.

### Localization

Text references are `(TextResourceId, TextKey)`, written `"package/key"` or just `"key"` within a package. What a message takes (`Text`, `Number`, a choice of names) is read from the source-language Fluent, so the contract and the wording cannot disagree. Read models return `BoundText` (a reference plus typed values); only the central formatter renders a locale. Publication analyses every Fluent branch, reference and argument use. `LanguageSource` composes content contracts with the selected packs; each resource is parsed once per locale and kept. Details and commands are in [workflows](WORKFLOWS.md#editing-and-validating-gameplay-content).

### Known limits

- Caps on how many of something content or a playthrough may have are gone. What bounds remain guard against endless or exponential work (nesting depth of conditions and actions, the predicate expansion budget, script steps and memory, 256 queued steps per command), against one mistake exhausting memory (the size of each file read, 4,096 stacks per inventory), or are rules of the game (party size, eight lined-up intents).
- Every character has a record in memory, about 1 KB each with stats kept as maps keyed by name. Only inventories are made lazily.
- The rules know nothing of range or line of sight; the engine adapter decides who can reach whom before it sends an intent.
- The game uses these crates only through the opt-in `--story` slice ([`app_game/src/story.rs`](../crates/app_game/src/story.rs)): conversation, quest, gate state, saves, area occupancy for the party, triggered walks, ambient lines, the character sheet, lessons and sparring with a dummy. Walks are straight lines; there is no pathfinding.

## Environment authoring

Reusable typed presets and compositions feed ordered spatial layers with coverage masks. One compiler derives ground palettes/weights, vegetation fields and generated objects. Empty coverage uses the world's explicit base material. Terrain surfaces have semantic IDs; texture-set array layers are resolved during cooking.

Curved roads have stable source geometry and shared styles controlling wheel tracks, center/shoulder wear, vegetation retention and relief. Relief is derived from original source heights, never repeatedly added to previous output. Explicit junctions connect 2–4 compatible arms. Spatial certification, intersections, samples and output work remain budgeted; querying one region must not recursively load the entire route network.

Asset collections deterministically scatter registered visuals with weights, scale/spacing, slope and clearance controls. Generated placements are render-only and are not individually editable source objects. Manual object placements remain separate and preserve stable identity.

Asset management currently consists of local source/runtime files, tracked pack manifests, SQLite asset/LOD records, a searchable editor placement palette and collection selection. `world-cook import-assets` validates a bounded RON catalog and local file availability, then registers stable key-derived IDs transactionally through `ProjectWriter`. Reimports refresh supplied variants and preserve unrelated records, placements and definition aliases. Asset conversion remains an offline tool, without an editor import UI. The Forest Tree Starter Kit summer catalog includes 11 trees and 8 shrubs with four mesh LODs each; licensed binaries remain ignored local files.

## Terrain and streaming

The default terrain hierarchy supplies distant coverage, bounded material streaming, smooth geometry transitions and nearby detailed shading. `--terrain-legacy` selects the older nearby world renderer for diagnostics; it does not change publication. Normal cooking includes distant material products and requires prepared CPU inputs. `--geometry-only` is an explicit fixture option.

[Database transport](../crates/engine/src/world_streaming/database.rs) owns worker startup, bounded channels and shutdown. Its protocol and immutable-reader queries depend only on `world`/`world_db` data, not terrain-rendering or residency modules. Source and terrain/material consumers submit requests without blocking; the streaming coordinator routes replies and owns world/index state and transitions. [Source residency](../crates/engine/src/world_streaming/residency.rs) separately owns page requests, asynchronous decoding, admission, cooling, statistics and stale-result rejection. A staged generation can answer terrain queries, but source reads remain on the active generation until the exact commit is acknowledged.

Dropping the worker disconnects a separate cancellation channel before joining. Both request and reply waits can then exit even when queues are full; an already-running synchronous SQLite read still finishes first. Runtime worker omission/restart is not a supported streaming mode.

[Attachment](../crates/engine/src/world_streaming/residency/attachment.rs) converts prepared pages into CPU sources, objects or legacy terrain entities, tracking page-owned meshes, materials and images for removal. Whole-page object validation and fallible terrain preparation finish before spawning entities or storing owned assets. Cooling retains ownership for two seconds and can revive the same entities. World/generation changes clear pages and cancel decode jobs without reusing pending request identities; same-world hierarchy rebases preserve canonical sources. These internal systems remain ordered inside `WorldStreamingSystems`; residency omission or runtime suspension is not a supported mode.

Important invariants:

- Cooked heights are f32 values on one world-wide 1/1024 m grid, and normals keep 12 bits per octahedral axis (about 0.05°). Constructors round both, so editor previews, cooked pages and decoded runtime data hold identical values, and shared edges stay bit-identical because the grid never depends on the page. The [codec](../crates/world/src/terrain_heightfield_codec.rs) stores planar-predicted integer steps: terrain nodes and height pages are about 40% of their previous zstd size on the hill fixture. CPU grounding/raycasting and grass placement interpolate the same piecewise-linear triangles as terrain geometry, not a different bilinear surface.
- Parent nodes decimate heights exactly but filter normals (3×3 tent; border samples filter only along their edge, so neighbours share codes). Point-sampled normals made distant lighting change at every level switch.
- Parent coverage must not fill holes. Retain a complete active cover while replacements load; parent/child transitions, stitched edges and morphs must remain crack-free.
- Geometry/material visibility and detailed source demand are separate. Elevated views must not demand finest leaf geometry everywhere below the camera.
- Actor contact outranks vegetation/contact and visual refinement. Grass may be retired atomically under pressure; actor grounding must not disappear. Readiness checks use the drawn surface, including transitions.
- Coarse material fallbacks remain available while fine products stream. `TerrainProfile::composite_minimum_level` limits which composites are published: roots and levels at or above it. Leaves below that level are evaluated in memory and filtered straight to it, so finer cores are never staged. Exception: when a root lies below the level, the space starts at the leaves. Cores at that level and above are cached in `<project>.cook-cache.sqlite`, one entry per node, keyed by node and fingerprint. The fingerprint hashes every evaluation input, so a cook evaluates only groups whose inputs changed; a test checks that the result is byte-identical to an uncached cook. The cache is deletable. Evaluator changes that alter output must change the fingerprint salts, as for the runtime's own fingerprints. Streaming never requests finer tiles, and the editor's live preview evaluates unpublished leaves from their published pages as the cook did. Zero (every level, the default) preserves previous output; each step quarters the finest stored texel density. Near detail uses existing hierarchy geometry, not another coincident ground mesh. `TerrainMaterial` remains shared by near-detail preparation and editor previews even if legacy world rendering is later removed.
- Rebase, source edits, publication and shader changes invalidate the appropriate caches. Obsolete asynchronous results cannot replace a newer revision.

Current source-stream limits include 16 pages loading/decoding/waiting for attachment, two actual page attachment attempts/frame, 64 MiB decoded source residency and 256 MiB estimated source GPU residency. Transport separately holds at most 16 queued requests and 32 replies; draining those queues does not bypass source-page admission. Hierarchy geometry/material caches have separate budgets. These counters are not total process/GPU memory. Admission skips blocked pages when a later page fits; priority eviction and aggregate pre-decode byte reservation remain open.

[ObjectLodPlugin](../crates/engine/src/object_lod.rs) owns visual-object LODs after transform propagation. Streaming includes it for game/editor; collection previews can use it without database streaming. Each object spawns every LOD as a child scene, and the plugin gives their meshes Bevy visibility ranges: a LOD's band runs between the distances where the object's projected height crosses the previous LOD's threshold and its own, and neighbouring LODs dither into each other over ±10% of each switch distance instead of popping. Projected height is the object's height seen side-on at its distance (logical pixels per metre × the 0.25–4 `VisualLodScale` clamp), so pitching the camera never changes LODs; projecting the root-to-top segment shrank when the camera looked down and switched trees under a top-down camera to their coarsest LOD. Ranges are rewritten only when window size, field of view or Object detail change; new LOD scenes are ranged when they finish spawning. Directional shadow cascades resolve the same ranges from the main camera. Residency reads LOD telemetry (the band containing the camera, ignoring crossfades) through accessors. Without the plugin every LOD would draw.

The [cover planner](../crates/terrain_render/src/lod/mod.rs) finds edge neighbours by walking the quadtree (up for coarser, down through split nodes for finer; [neighbours](../crates/terrain_render/src/lod/neighbours.rs)) rather than testing every pair. It produces identical covers with about 70× less work, so budgets are no longer limited by pairwise checks. Desktop budgets are 2,048 patches, 4M triangles, 512 metadata requests per plan and a 384 MiB mesh ceiling; iOS keeps 512 / 1M / 128 / 128 MiB until measured on a phone. Plans run on the async compute pool whenever the view or contact demand changes, from snapshots of their inputs (descriptors are shared and copied only if a reply lands mid-plan); `TerrainLodStats` reports their count and last duration (about 6 ms at the full desktop budget on M2 Max). A plan starts only while no target is staged, so the drawn cover and the descriptors it reads cannot be replaced or evicted before its result applies; live authoring cancels a running plan. A plan equal to the drawn cover stages nothing. Changed covers use a staged morph, so initial loading remains progressive. Plans return missing metadata most urgent first and the engine loads 128 keys per plan, so actor and grass contact always precede visual refinement. A blocked root balance requests every missing split in one plan. The descriptor table holds 12 entries per patch of budget (24,576 on desktop): the drawn and staged covers, their ancestors and loaded children. It must never fill, or new ground stops loading. Descriptors and decoded samples that leave the cover stay in small least-recently-used caches (4,096 descriptors, 8 MiB of samples). A new cover evicts cached samples before its budget is checked. Each plan requests every missing descriptor in batches of 128, with up to 12 database queries and 8 mesh builds in flight. Refining a patch needs its four children, so one batch per plan grew a cover by only about 100 patches per plan-and-morph cycle. A moving view re-plans at most 10 times a second, except while drawn ground does not yet satisfy contact demand. The planner keeps its node sets in fixed-seed hash sets beside the ordered cover, and a morph's common cover walks ancestors (0.4 ms for two full covers, from 8 ms pairwise). Contact checks for grass pages and actors use an index of the drawn cover's footprints and certificates, filed by node square. The index is rebuilt only when the cover or a running morph changes. Each morph indexes its old and new covers once, so the per-frame cost does not grow with the patch budget.

Terrain geometry and baked colour/normal detail choose refinement by a rotation-independent pixel-error bound: 3D camera-to-patch distance, projection scale and the worst angle within the view cone. Orthographic demand uses projection scale alone. Camera turns therefore keep the same resident cover and detail tiles; frustum culling only decides which meshes draw. Moving the camera still refines/coarsens terrain, with the existing hysteresis, contact priorities and hard budgets. The full desktop budget may remain resident even while looking away from mountains; this avoids the coarse geometry and material fallback that appeared for several seconds on turning back. A budget-limited world can still exceed the requested visual error, and initial loading remains progressive.

Recently used GPU terrain meshes remain cached after leaving the drawn cover: up to 96 MiB on desktop or 16 MiB on iOS, within the existing mesh ceiling. They have no drawn entities. Target uploads and morphs evict optional meshes first; world entry and live height edits clear them. A reused GPU mesh must reload any evicted CPU height samples before publication because morph endpoints and contact checks require them. `TerrainLodStats.cached_mesh_bytes` reports optional residency. The separate baked colour/normal detail atlas holds 256 tiles on desktop (13.32 MiB) or 128 on iOS (6.66 MiB). Unneeded tiles stay warm while there is space; pressure retires old leaves before their fallback ancestors, with the existing fade. Neither cache changes geometry error thresholds or triangle budgets.

World views (the game camera and the editor's world camera) cull at `WORLD_VIEW_DISTANCE`, 20 km, past the island's far side; haze visibility comes from the world's atmosphere profile (60 km by default), not from start views. Bevy's default of 1 km hid kilometre-scale terrain. Depth is infinite reverse-Z, so this only decides what is drawn; terrain cost is still bounded by the hierarchy's screen-error LOD.

In the normal hierarchy path, static-object residency uses a separate 192 m camera-to-cell-bounds radius in all directions. Camera frustum visibility only prioritizes loading; it must not retire off-screen trees that can cast shadows onto visible ground. Bevy performs camera and shadow-cascade mesh culling independently. The descriptor window covers the larger of grass contact and object visibility ranges, within the existing 4096-cell query budget. Grass contact and gameplay demand keep their own ranges. This replaces the three-cell object limit that reduced visibility to about 24 m in 8 m worlds. An asset's last LOD may be a hemi-octahedral impostor (`*.impostor.json`, version 3, [tree_impostor](../crates/engine/src/tree_impostor.rs)). Its two atlases hold each view's crop as equal tiles. The first holds colour and coverage. The second holds an octahedral normal, the surface's depth toward the viewer and crown occlusion. The second is loaded as linear data, since Bevy decodes UASTC as sRGB unless told otherwise. The shader lights each pixel at the depth-corrected surface. Where it takes over from its mesh LODs, the quad bends in the wind as its far mesh LOD's trunk does, less farther out, and not at all by 2.5 times that distance or past 450 m: the descriptor carries that LOD's wind profile and stem height, the impostor material binds the trees' wind buffer, and its bottom, middle and top vertex rows follow the trunk's arc. Cells never draw it: every cook regroups the static objects whose asset ends in an impostor into far-object pages per block of 16×16 cells (`far_object_pages`, [far_objects](../crates/world_db/src/runtime/far_objects.rs)), and the game streams blocks within 2,048 m ([far_objects](../crates/engine/src/world_streaming/far_objects.rs)), drawing one batch per impostor per block. Objects whose last LOD is an impostor switch at a distance, with 4% hysteresis, and then dissolve old into new over 0.6 s ([object_lod/timed](../crates/engine/src/object_lod/timed.rs)). Fading meshes carry their dither level in their mesh tag, which the tree shaders read in every pass, so shadows dissolve too. In the shadow passes the levels are doubled, so shadows overlap: the incoming LOD's shadow is whole by mid-fade and the outgoing one's stays whole until then. The impostor's level goes into its instance's slot in a buffer shared by all impostors (`ImpostorFades`), found by world position. An instance no resident object controls is drawn, so a tree whose cell is still loading shows its impostor and fades to its mesh when the cell arrives. The hand-off stays within 166 m (`IMPOSTOR_HANDOFF_METRES`), inside the object residency. Impostors cast no shadow-map shadows. Their crown and forest self-shading applies at every distance, darkened further by the shadow maps where those are darker. Assets without an impostor keep their final mesh LOD below its threshold. The LOD lab ([lod_lab](../crates/engine/src/lod_lab.rs), `yarra-app-game --lod-lab`) spawns a cataloged tree outside streaming with the same chain: mesh scenes, and its impostor as a batch of one. A `ForcedLod` on its object overrides the visibility ranges, so any representation can be drawn at any distance. The legacy diagnostic path retains its three-cell window. Source memory and attachment budgets still apply, so 192 m is a demand limit, not a guarantee under memory pressure. Pages share asset variants, so the GPU budget counts each variant once across resident pages, and impostors not at all (far-object blocks own them). Every drawn far-object batch also feeds the distant forest shadows ([forest_shadow](../crates/engine/src/forest_shadow.rs)): crowns (from each impostor's baked crown metadata) are rasterized off the main thread into a 4 km map around the camera ([atmosphere::forest_shadow](../crates/atmosphere/src/forest_shadow.rs)), and past the shadow cascades every cloud and terrain material marches towards the sun through it, so distant crowns shade each other and the forest floor as the shadow maps do near the camera.

The local material supports one/two active surfaces despite the data contract allowing eight slots. Albedo is sRGB; normal/AO/roughness and macro maps are linear. Prepared albedo and stochastic-buffer references remain available. Nearby detail blends to baked ground; material preparation must preserve shared borders and fallback behavior.

## Vegetation

The runtime joins compact vegetation fields with terrain surfaces, generates candidates on the GPU, and emits bounded indirect draw bins for single/split topology and high/low geometry. It does not store an entity or database row per blade. Stable ownership, seeds and thinning preserve placement across views; telemetry exposes capacity drops.

The [renderer entry point](../crates/vegetation_render/src/renderer.rs) owns render-world composition and resource initialization. Internal modules separate CPU/WGSL layouts (`gpu_types`), CPU scene/LOD packing (`packing`), fixed index templates (`topology`), allocation/bind groups (`buffers`), pipeline specialization (`pipelines`), uploads/view inputs (`prepare`), cached placement dispatch (`generation`), opaque queue/draw (`draw`), and optional counter readback (`telemetry`). Candidate caching, blade preparation, temporal rendering and asynchronous canopy work retain their existing owners. Scheduling remains explicit at composition, including temporal dependencies and the iOS readback exclusion; these modules are not independently removable plugins.

Placement, source acceptance and per-frame blade deformation use separate caches. Wind phase must not invalidate source acceptance/placement unnecessarily. Prepared-blade overflow evaluates the original vertex path rather than dropping grass. Tests compare accepted instance multisets and rendered output, not append order alone. A scene revision uploads only the samples of pages that arrived or changed. `WorldVegetationPlugin` gives every page a content key, renewed when its field or terrain page changes and kept across rebases. [Page slots](../crates/vegetation_render/src/renderer/page_slots.rs) keep each keyed page's surface and coverage samples at a fixed range and free ranges when pages leave. Work items, species choices and species depend on the whole resident scene, so they are rebuilt each revision; they are small. Scenes without keys, such as editor previews and fixtures, are packed in full, as before. The acceptance cache is still rebuilt after every revision; keeping it for unchanged pages was not worth the work, since its measured saving is ~0.05 ms.

[WorldVegetationPlugin](../crates/engine/src/world_vegetation.rs) composes the renderer, published field/terrain joining, logical LOD focus and ground-canopy integration. The game installs it explicitly after world streaming; F1 applies settings before its update set. `VegetationSceneState` and `VegetationView` name the production render snapshot and camera opt-in. The serialized `VegetationDebugSettings` type remains unchanged for saved-study compatibility; its production and diagnostic fields still share one resource.

Game and editor share terrain-to-vegetation conversion and [GroundCanopyPlugin](../crates/engine/src/world_vegetation/canopy.rs). The editor retains authority over accepted draft catalogs/coverage and workspace selection. Terrain and vegetation keys match by space/cell/LOD and extent, ignoring their different page domains. Source joining continues while grass rendering is disabled, and clears stale pages when the world/catalog disappears. Joined in-place edits invalidate the snapshot; unrelated terrain pages do not.

The canopy cache keeps one immutable source snapshot plus per-tile indices. It compares actual nearby sources, including relief, before accepting bake results. World/origin/catalog changes, material replacement and unload release affected masks and cancel jobs. Disabling canopy detaches coverage and cancels jobs, retaining valid resident masks for reuse; source edits are checked before reattachment. Scheduling remains capped at two jobs after 0.35 seconds of source settling. Canopy updates run in `Update`, before terrain material preparation in `PostUpdate`. This replaces the two separate game/editor caches; no performance improvement has been measured.

[TreeWindPlugin](../crates/engine/src/tree_wind.rs) is installed explicitly by game/editor composition. It reads the existing `VegetationWind` direction, strength, gust field and phase; the vegetation renderer remains the clock owner, including external editor/replay transport. Legacy `extras.yarra_wind = "foliage_uv1_v1"` opts static, alpha-masked foliage into UV1 `(flutter, branch)` deformation with rigid bark; `TreeWindResponse` supplies that path's response in metres. Current vegetation bundles opt both bark and foliage into `hierarchy_v2`, requiring `_WIND_PIVOT` and `_WIND_AXIS` on every primitive. There are no path-name/prefab heuristics or database schema changes.

The new attributes store the primary limb root/tree height and limb direction/compliance. Authoring assigns descendants and cards from the complete skeleton before LOD thinning. The shader curves the planted trunk, transforms each primary limb with its attachment, then applies camera facing and pinned card flutter. `wind_profile` stores species compliance, height-based response period, flutter gain and foliage load. Four coherent bands filtered by a damped response drive motion; this is an artistic shallow hierarchy, not measured turbulence or per-joint physics. Trunk/limb angle caps bound extreme settings and swept mesh bounds. Ground stems keep separate feet; secondary twigs inherit the primary limb; collision and weather-shelter footprints remain in the rest pose. Current instances use uniform scale.

`TreeWindTuning` supplies session-only F1 overrides and response gains. Automatic wind is restored before weather updates each frame; a separate smoothed manual pose is applied in PostUpdate before extraction. Returning to weather therefore resumes its current automatic values. External editor/replay wind bypasses the manual override. Strength, gustiness and direction affect the shared vegetation field; tree response gains affect the connected hierarchy. F1 labels refresh after `TreeWindSystems`; capture context records tuning, while A/B Restore does not restore it.

Tree materials extend the existing cloud-shaded PBR material, preserving textures, alpha clipping, normal maps and cloud transmission. Connected bark keeps its upper/lower texture blend in the wind material; the legacy bark converter skips that tag. Tagged foliage explicitly opts into that pipeline in isolated collection studies, where the study atmosphere disables cloud transmission; unrelated study materials retain their ordinary path. Conversion follows cloud material conversion and retries until scene dependencies and bounds exist. Instances share cached materials, source edits propagate, and unloading scenes releases the cache's references. Mesh bounds include the maximum allowed deformation. One shared 192-byte GPU buffer carries two 96-byte current/previous wind poses, so time updates do not rewrite per-instance transforms or dirty every material. Independently reduced f64 phase offsets preserve the field across floating-origin rebases. Foliage also tagged `extras.yarra_shading = "crown_v1"` (the Houdini trees) is lit by its crown: back faces keep the authored crown normal (Bevy's two-sided flip is turned off; back faces are still drawn), `|N·V|` replaces `N·V` so a card seen from behind is not treated as grazing, and `COLOR_0` is crown occlusion applied to indirect light only (`TREE_CROWN_SHADING` in the cloud material shaders), because shadow maps already darken the sun.

Colour, depth and shadow passes evaluate identical tree geometry. The motion-vector prepass evaluates the previous model matrix with the last GPU-submitted wind pose, including its settings and origin; it does not reconstruct history from a time delta. This supports MetalFX Temporal and Bevy temporal consumers, paused/scrubbed transport and wind toggles. PostUpdate replay producers run before `TreeWindSystems`. New LOD topology still uses the renderer's ordinary history rejection; LOD switches crossfade by dithering (see ObjectLodPlugin), which does not guarantee shimmer-free foliage. A native GPU regression checks animation, pause, zero weights, disable and rebase cases, and the game path has been exercised with MetalFX Temporal.

Canopy shading is a shared artistic treatment of ground and lower blades, not physical grass self-shadowing. Source-boundary/coverage bakes run asynchronously with revision checks and bounded scheduling. Shading controls must not trigger unrelated placement/pose rebuilds. Grass casting onto ground remains unresolved; previous proxy casters were removed after visual rejection.

## Atmosphere and presentation

One authored atmosphere/weather profile belongs to each world space. Pure evaluation lives in `world`; the Bevy adapter owns sky, directional/ambient illumination and haze. The game advances the time of day ([`GameDayClock`](../crates/engine/src/day_clock.rs)): the day phase moves at the profile's `day_seconds` (20 minutes by default) from the authored start or `--time HH:MM`. Profiles, repros, look and LOD-lab captures hold the time they start at unless `--day-clock on`, and F1 A/B captures pause it. Editor studies/preview transport can temporarily own the phase. Restoring a workspace must restore the correct owner and camera environment.

The [sky composite](../crates/atmosphere/src/sky.rs) draws everything between the camera and the scene in one pass over the resolved HDR image, after the main passes: the physical sky and sun/moon disks and aerial perspective from Bevy's atmosphere tables, the cloud layer, ground haze, valley mist and weather fog. Bevy still computes those tables and lights surfaces through them; only its own sky pass is replaced, by a no-op in the same schedule slot (found as the only system whose sole constraints are after the opaque pass and before the transparent pass, apart from the public transmissive pass). That pass drew into the multisampled colour target, so multisample colour had to be stored and reloaded every frame, and it fogged whole pixels from one depth sample. The composite reads every depth sample: sky samples get the sky's light and geometry samples the haze of their own distance, and the resolved image is multiplied by the transmittance averaged over geometry samples only, because sky samples hold the black clear colour. Pixels whose samples share one distance are shaded once. Transmittance is per channel through dual-source blending where the GPU supports it. The composite needs sampled depth, which Bevy requests only for atmosphere views, so `WorldEnvironmentView` cameras request it themselves. Aerial-perspective transmittance integrates the medium's extinction along the camera-to-surface segment (Simpson's rule over Bevy's full-precision density table, bound at 5/7). Bevy's segment lookup divides two whole-atmosphere transmittances that underflow its half-float table for near-horizontal ground rays, which drew coloured horizontal streaks on distant terrain. The F1 sky switch stops the composite drawing sky and haze but keeps Bevy's tables, so surface lighting does not change with it.

Exposure follows the profile's EV; in the game, eye adaptation ([adaptation](../crates/atmosphere/src/adaptation.rs), Bevy's auto exposure) then follows half of a change in the scene's metered brightness around a forest edge in sun, within +1.5 / −1 stop, quickly towards brighter scenes and slowly towards darker ones. The sky band counts for 30% in metering. It is a game-only presentation setting (F1 **Auto exposure**); editor and studies show the exposure as set. Bevy keeps adapting a view whose `AutoExposure` is removed, so turning it off swaps in an identity compensation curve. Under tree crowns the sky light is held back as well ([`ForestSkyOcclusion`](../crates/atmosphere/src/forest_shadow.rs), `forest_sky_visibility`): the forest-shadow crown map carries three mip levels (8, 16 and 32 m texels) that hold the average share of sky its crowns let through (`exp(−density)`) and the highest canopy top, and a point reads them once, between 8 and 16 m texels, with a 15% floor. Bevy rewrites only level 0 of an existing texture when an image changes, so the render world uploads those levels itself (`ForestSkyLevels`). World cameras use Khronos PBR Neutral tonemapping (`WORLD_TONEMAPPING`). Terrain, bark, characters and grass apply it to their ambient term; tree foliage and impostors keep their baked crown occlusion. The sky the crowns hide is partly replaced by leaf-filtered light (`CANOPY_FILL`, a dim green-gold share of the sky's light), so shade under crowns is not sky-blue. Below its own horizon a surface sees ground, not sky: in `clouds/pbr_lighting.wgsl` the lower half of a normal's view takes the light the ground reflects (`ground_light`: a green-gold albedo times the sun and moon through the atmosphere and cloud shadow, plus the sky), dimmed under crowns. Before, trunks, characters and cliffs were lit only by blue sky light from every side and read purple-blue in shade; flat ground is unchanged. Grass reads the map through the shared cloud surface bind group.

Every weather has two layers of low air, authored per world in `AtmosphereProfile::fog` ([`FogSettings`](../crates/world/src/fog.rs), the `FOG1` atmosphere extension after `WTH1`) and drawn by the sky composite in front of the aerial perspective, mixed with weather fog by optical depth. **Ground haze** thickens exponentially towards the sea (30 km visibility at sea level, thinning by e every 250 m), integrated analytically along each ray, so ridges stand out of hazier lowlands. **Valley mist** pools in low ground under a level top, so hills rise out of it. Its [map](../crates/atmosphere/src/valley_mist.rs) is built once per runtime generation from the terrain: the engine reads every level-4 node (16 m samples; 400 nodes and a 641² map for Reteya) through the database worker, a few requests at a time with ids of their own, and builds the map off the main thread ([`world_streaming/valley_mist.rs`](../crates/engine/src/world_streaming/valley_mist.rs)). Per texel it holds the mist floor (the lowest ground within 256 m, smoothed, so the floor reaches up a valley's sides and the top above it stays level), the valley share (ground below its surroundings) and the land share (mist fades out within about 200 m offshore). Open ground holds 35% of a valley's depth and 20% of its density. Along a ray, mist is integrated exactly in four stretches of the part that runs below the higher of the mist tops at its ends, each with the top and drifting cloud-noise wisps at its middle; where depth samples differ (silhouettes), haze and mist are evaluated at the nearest and farthest sample and interpolated. Mist is lit by the sky (and moon) evenly and by the sun mostly forwards, through the same cloud-deck attenuation as weather fog. Ground haze scatters at least the colour of the sky just above the horizon below each ray, read from Bevy's sky table, and never less than its own sun and sky light (the aureole towards the sun, which light shafts take back where the haze lies in shadow; with the horizon colour alone they took back more than it had and left a cyan glow towards a sun rising behind trees): haze and sky are the same air, so distant haze meets the sky without a band at any time of day (a separate estimate of its light left a grey band over the sea once the sun was dimmed by the atmosphere); at night the authored fill light is added. Distant clouds lost in haze likewise turn into the sky they stand in. Under a closing deck (`CloudParams::weather.z`, 0 open to 1 overcast) both blend to the deck's grey instead, and the deck continues to the horizon at its lowest traced elevation rather than fading out past 20–40 km, which had left a band of clear sky between the deck and the sea. The mist amount follows the sun: authored amounts at night, sunrise, high sun and sunset, with morning mist burning off by 40° of sun elevation (8 am, the default start, keeps about a third of the dawn amount); wet ground after rain adds to it and strong wind thins it. F1 **Fog & mist** and `--profile-fog` turn both off; weather fog stays.

[Light shafts](../crates/atmosphere/src/light_shafts.rs) are sunbeams through the air near the camera, computed before the sky composite at a quarter of the main-pass resolution ([shader](../assets/shaders/sky/light_shafts.wgsl)). Each texel marches its view ray in 32 steps, packed towards the camera and offset per texel by interleaved gradient noise, over the range the sun's shadow-map cascades cover (at most 150 m). The cascades are orthographic, so each ray's shadow coordinates are blended between its two ends rather than projected per step. The composite lights ground haze and valley mist as if the sun reached all of it; the march gives back the sunlight of haze and mist in shadow. It adds the humid **air under crowns**, which only this pass draws: `FogSettings::canopy_air_visibility_metres` (500 m by default, denser with the morning mist) under the canopy of the forest-shadow map. That air scatters sunlight where the shadow maps let it through and a dimmer, leaf-green share of sky light everywhere. Shadow lookups are skipped where only the thin ground haze would be darkened, and mist is evaluated only below its ceiling. Each texel stores the light to add, the air's transmittance and the distance it marched to; two depth-aware blur passes remove the step noise, and the composite blends the result in with a depth-aware upsample, so there is no extra full-screen pass. F1 **Light shafts** and `--profile-shafts` turn it off; it also needs Fog & mist. Cost: within noise in the broadleaf forest and about 0.5–0.9 ms on the open start beach (morning mist there is shadowed too).

The sun ([`sun_glare`](../crates/atmosphere/src/sun_glare.rs), [composite](../assets/shaders/sky/composite.wgsl)) is drawn by the composite instead of Bevy's flat disc: limb-darkened, with its exposed light kept within half floats. The haze and mist phase function has a narrow aureole lobe (5%, g 0.92), so the sky and distant haze brighten right around the sun. Glare of the eye and lens is drawn analytically around the sun's direction: a core about a degree wide holding 2% of the sun's light and a veil over tens of degrees holding 1.2%, scaled by how much of the sun the camera sees. A one-workgroup compute pass measures that ([shader](../assets/shaders/sky/sun_occlusion.wgsl)): with the disc on screen, 64 depth samples across it count the sky behind; off screen, 64 shadow-map samples on a 0.4 m patch around the camera tell whether something blocks it. The cloud shadow at the camera dims both, and the result eases in over a few frames, so walking through leaf shadow does not flicker the glare. Bevy's bloom downsample suppresses small, very bright sources, which is why the disc alone barely bloomed.

**Sunlight through the atmosphere** ([`sunlight`](../crates/atmosphere/src/sunlight.rs)). Bevy dims and reddens the sunlight on surfaces with its transmittance table; the effects that light the air themselves (ground haze, valley mist, weather fog, light shafts, particles, rain and the cloud layer) now use the same light. Each frame the CPU integrates Bevy's medium (Rayleigh with the profile's molecular density, the near-ground aerosol of the view's visibility, ozone) along the sun's direction over the curved atmosphere, once at the camera (`CloudParams::near_sun`, and `air_sun` for haze and mist) and once at the middle of the cloud layer (`sun`, `sun_color`), and drops the part of the disc below the horizon. Before, they used a grey estimate that at 5° elevation gave the haze about seven times the light reaching the ground, and no red, so sunsets showed a grey-white horizon band. Clouds keep their light longer than the ground: from 2 km the horizon lies 1.4° down.

**Sun and twilight.** The profile has one sun above the atmosphere (`sun_srgb`, `sun_lux`); Bevy's atmosphere alone reddens and dims it towards the horizon, for surfaces and sky alike. The phases (night, sunrise, day, sunset) author only the sky light. Before, each phase carried its own warm sun as well, which the atmosphere reddened a second time, so the twilight zenith went brown instead of blue. The sun fades out of the sky between 10° and 18° below the horizon and renders shadow maps only while it is up. After sunset the sky light takes the night's hue by 4° down while it dims, paler until night (`TWILIGHT_PALE`), instead of the sunset's lilac; together with Bevy's sky this read purple. **Adaptation** (`EvaluatedAtmosphere::adaptation`, the square root of the night weight) drives exposure and the loss of colour: it runs ahead of the night's light, so the minutes after sunset no longer read darker than the night.

**Night** loses colour: world views get Bevy's `ColorGrading` with post-tonemapping saturation falling by `NIGHT_DESATURATION` (60%) with adaptation, as eyes adapted to moonlight see little colour, so moonlit scenes stay readable without looking like a blue day. The **moon** ([`NightLighting`](../crates/world/src/atmosphere.rs)) follows the sun's path, lagging behind by its elongation, which grows a turn per synodic month from the authored age at the first day's midnight (`age_days`, 10 by default: waxing gibbous). The game clock counts days (`AtmosphereState::day`), so the moon rises about 50 minutes later each day and goes through its phases every 30 game days. Moonlight is art-directed: the authored full-moon illuminance times the lit share to the power 1.5 (a half moon gives about a third), only at night, fading out over 3° after the disc has set, and partly balanced above 12° elevation so a high moon lights open ground about 1.4 times as much as a low one rather than 3.7: the night keeps its tone as the moon climbs. The composite draws the moon itself (Bevy's disc is off): a sphere lit from the sun's direction with Lommel–Seeliger reflection, so a full moon is evenly bright to its edge, with earthshine on the dark side and a coarse map of the near side's seas and bright craters at their real places, oriented by the pole of its path. By day it is drawn as the sunlit moon (pale against the sky); at night dimmed to stay readable at the night exposure, so its seas show. Its glitter on the sea is its drawn face's image, much brighter than the averaged glitter would make it, since wave facets each mirror the whole disc. A moonless sky keeps a faint glow (airglow and starlight, at least 15% of the night's sky light near the horizon), so it never turns black over lit ground. Neither light is ever hidden: Bevy 0.19 loses a directional light's shadow casters once it has been hidden and shown again, so a dark light only stops rendering shadow maps (`AtmospherePresentation::shadows` holds the quality setting). The composite draws **stars**: at most one per cell of a 160-per-unit grid over the sky's directions, at a hashed spot away from the cell's edges (about 5,000 above the horizon, mostly faint, white to pale blue or orange), about a pixel wide in exposed units. They come out as twilight ends (sun 3–11° down) and sit behind the moon, clouds, haze and the atmosphere's transmittance. The crowns' wrap-around and see-through light, added outside Bevy's `directional_light`, goes through the same atmosphere transmittance and visible share of the sun's disc (`through_atmosphere` in `clouds/pbr_lighting.wgsl`); before, foliage stayed white-lit at sunset and lit after the sun had set, because the sun keeps lighting Bevy's twilight sky well below the horizon.

**Sun rays** ([`sun_glare`](../crates/atmosphere/src/sun_glare.rs), [shader](../assets/shaders/sky/sun_rays.wgsl)) reach past the shadow maps. After the occlusion pass, at the light shafts' quarter resolution, each texel walks 32 samples along its line to the sun on screen, packed towards the sun and weighted by the veil there, and records the share that is open sky (off screen, the share of the sun seen stands in). The composite multiplies the glare's veil by it, plus an **air glow** around the sun (5% of its light, 0.15 rad wide), so beams fan out from trunks, crowns, ridges and buildings in front of the sun. The air glow is drawn only while the sun is in or near the image, and builds up over the first 200 m of depth (faster in the air under crowns, from the light shafts' transmittance), so near ground and hills in front of a low sun are not washed out. F1 **Light shafts and sun rays** and `--profile-shafts` turn both passes off.

[Ambient particles](../crates/atmosphere/src/ambient_particles.rs) are drawn like the rain: instanced quads in camera-anchored boxes that wrap a world-fixed lattice, with hashed positions, periodic motion of whole cycles per hour (so the wrapping clock never jumps) and a wind drift accumulated on the CPU, so nothing is simulated per particle ([shader](../assets/shaders/weather/ambient.wgsl)). There are three kinds. **Dust motes** fill a 6 m box just ahead of the camera. **Seed fluff** fills a 5 m layer over the ground of the valley-mist map, 28 m across. **Falling leaves**, 36 m across, exist only under crowns of the forest-shadow map: each falls from a height in the crown it left, traced back along the wind, to that map's ground, swinging, tilting and tumbling. Motes and fluff are lit through the sun's own shadow-map cascades (read with Bevy's light uniform and comparison sampler, not its view bind group), the cloud shadow and the crowns' sky occlusion, with Henyey–Greenstein forward scattering, so motes show in sunbeams and against the light; leaves are lit two-sided. Motes keep to shade under crowns, where sunbeams read; seeds favour open ground. Tiny particles are drawn at least three pixels across, as soft dots that keep the light of their true size. Motes and fluff need a dry day: rain clears them and wet ground thins them, while wind adds fluff and shakes leaves loose. F1 **Ambient particles** and `--profile-particles` turn them off. Cost is within measurement noise (under 0.1 ms).

Balanced clouds use a 2048×256 azimuth × elevation sky panorama (square-root elevation warp, rows along the horizon) refreshed a few rows every frame, four complete refreshes per second at any frame rate. The sky composite cross-fades the two latest complete refreshes while a third image is refreshed, so clouds change continuously rather than in 4 Hz steps behind a moving refresh seam; High retains per-frame half-resolution rendering. Cloud altitude, field size, seed or enablement changes, teleports and resume require a full refresh; coverage, density, erosion and thickness (weather) and normal evolution update progressively. Cloud Off skips cloud tracing and shadow passes but preserves weather fog, weather's ambient response and some shared bookkeeping.

**Cloud shapes** ([density](../assets/shaders/clouds/density.wgsl), [tracing](../assets/shaders/clouds/render.wgsl)). Broken cloud is cumulus: the body noise is sampled stretched upwards (half its horizontal rate), so each cloud is a column with one footprint from a flat base, and the threshold rising with height rounds its top, so strong cores tower and edges stay low. Worley billows are eaten out of the outline, and the density reaches its full value within a few tens of metres of it, 2.5 times a deck's. As coverage closes into overcast the deck keeps layered sampling (the layer's share of the noise period upwards) and a density that follows the noise, so its thin and thick parts give it texture. Light through a cloud has a direct beam, `exp(-τ)` times the phase, and a diffuse part that falls off as `1/(1 + 0.11τ)` (two-stream diffusion with g 0.85), so thick bases stay grey; bases also take sunlit ground's bounce (albedo about 0.1), which at midday equals the sky above them. The trace takes about 25 m steps, 48 to 160 of them (at most 80 at High, which traces every frame). The composite reads the panorama as a cubic B-spline in four bilinear taps, without which the sharp edges showed its texels as staircases; reflections in the sea read it bilinearly.

Game weather is [pure data in `world`](../crates/world/src/weather.rs): Clear/Scattered/Overcast/Rain/Storm presets, a weighted random sequence with hold/transition durations, continuous blending from the current values and a wetness integrator. Each world's `AtmosphereProfile::weather` holds its authored presets and sequence (persisted as the `WTH1` atmosphere extension after `CLD1`; untouched profiles keep their exact previous encoding), defaulting to the built-in values. The game adopts published edits live without restarting the sequence. The editor previews any preset, with a chosen wetness, over the edited or published profile; editor-owned atmospheres apply weather only as that explicit preview, and studies never do. Rain shelter and grass ambient gain are game-only, so editor previews rain under trees. The [engine adapter](../crates/engine/src/weather.rs) advances it in the game only (`AtmosphereOwner::Game`) and overlays it on the authored profile: cloud shape, daytime exposure and skylight colour through `AtmosphereState::effective_profile`, the grass ambient bound through `VegetationAmbientGain` (exposure adaptation, since grass lighting is bounded in exposed units), and the shared wind through `VegetationWind` strength, gusts and `rate`. Grass, trees and cloud drift share the authored cloud wind direction while weather is active. Weather changes the wind clock rate rather than `speed`, because phase is `time × speed`. Reduced visibility is not written into Bevy's scattering medium: its half-float transmittance tables divide values that underflow below a few kilometres and produced NaN streaks. During a weather change each region of the cloud field blends from the previous coverage, extinction and erosion at its own time (a noise-driven arrival over ~40% of the change) instead of one global threshold; cloud shadows share the same density function. Weather fog instead adds the missing extinction, lit by desaturated ambient light, per depth sample in the sky composite, outdoors only. `--weather authored`, the default for profiles, repros, captures and smoke runs, presents the profile unchanged. F1 A/B captures pause the weather clock and record the weather.

**Lightning** ([model](../crates/atmosphere/src/lightning.rs), [game schedule](../crates/engine/src/lightning.rs)) comes with storms: `WeatherParams::lightning_per_minute` rises to 8 with heavy rain under the densest clouds, so only the Storm preset (and changes into it) strikes, and the saved weather is unchanged. Strikes come at exponential intervals, 1.5–7 km around the camera, on the weather's clock (paused with it). A strike is a seed, the point it hits and its start: two to four return strokes tens of milliseconds apart, each a 35 ms pulse of the channel and a 60 ms flash, then the clouds' afterglow over the rest of 1.2 s. The channel is ten jagged segments from the cloud base to the strike point and three two-segment branches, drawn by the sky composite as a pixel-wide core and halo far past white (bloom spreads it), behind nearer geometry and dimmed by haze and rain fog. The flash lights the clouds near the strike (and their reflection in the sea), the haze and rain fog, and the ground through the ambient light (2,000 at the peak, bluish white): a night strike shows the landscape in grey for a moment. F1 → Weather **Lightning strike** forces one ahead of the camera; the look key `lightning=SECONDS` holds one that far in. No thunder: there is no audio yet.

[Precipitation](../crates/atmosphere/src/precipitation.rs) draws rain as instanced camera-facing streaks in three camera-anchored boxes (near, mid, far) that wrap a world-fixed drop lattice. Positions come from hashes plus a CPU-accumulated fall offset, so there is no per-drop state and wind changes never make drops jump. Streaks follow drop velocity relative to the smoothed velocity of `PrecipitationReference`, which the game sets to the camera's follow target so orbiting does not tilt the rain (teleports and origin rebases ignored; free cameras draw unstretched streaks), keep at least one pixel of width with proportionally reduced alpha, fade near the lens and with weather fog, and use a soft test against scene depth. The pass runs between `EarlyPostProcess` and `PostProcess`: after Temporal reconstruction (no ghosting, output resolution) or on the resolved MSAA image, and before bloom and tone mapping. Wetness from `AtmosphereState` reaches every surface through `CloudParams::weather`: the shared PBR adapter darkens albedo and lowers roughness on sky-facing surfaces, and grass darkens its body colour.

The [open sea](../crates/engine/src/ocean.rs) is render-only and has no mesh. A world space's optional `sea_level` (stored in both databases) is published while a world view is active as `atmosphere::SeaSurface`; the sky composite intersects each view ray with the sea's surface (flat out to 10 km around the view, then bending with the planet, so it reaches the sky's horizon from any height) and draws the water in front of whatever the main pass drew below it: the seabed, the foot of a rock, or nothing beyond the world's ground. Shore is wherever the terrain crosses the sea level. Through the water, the seabed is dimmed per channel by the column seen through (red goes within a few metres; `WATER_EXTINCTION`) and by its own light coming down (1.3× its depth), and the body adds the daylight it scatters back up (`WATER_ALBEDO`), so shallow water over sand is clear and greenish and deep water dark blue. The surface's waves ([waves](../assets/shaders/water/waves.wgsl)) are 24 deep-water waves from 60 m to 15 cm in a fan around the cloud wind, with directions, wavenumbers and frequencies in a constant table (whole cycles per hour, so the wrapping clock never jumps), each equally steep so that together their slope variance follows Cox and Munk's measurements for the weather's wind strength. Waves under about three pixels long drop out (the loop stops at the first, since they run longest first) and their slope variance becomes roughness, so far water spreads the sun into a broad glitter path instead of shimmering. Gust patches a few hundred metres across, from the cloud noise and drifting with the mist, roughen it unevenly. The surface reflects the sky and the cached cloud panorama with Fresnel (blending to the deck's grey under overcast), and the sun and moon through GGX glitter shaded by cloud shadows (the cloud shadow map is bound to the composite) and hidden by a closing deck. In the first 30 cm of depth a swash runs up and drains back every 9 s, its phase varying along the shore: a lacy foam front rides it with fainter foam behind, sand it drained from stays wet and darker, and a film of water fades in over the first metres. Widths along the ground become depths through the seabed's slope, estimated from the depth buffer two pixels away, so a nearly flat beach gets a thin foam line rather than sheets, and nothing starts hard at the dry edge, where the terrain's contour zigzags. Rain leaves no splashes below the sea level. Cost: about 0.2–0.3 ms at game scale with the sea filling most of the view or at the waterline. Not implemented: refraction, the view from under water, swimming, breaking waves, lakes and rivers.

[Rain shelter](../crates/atmosphere/src/shelter.rs) is a 256² top-down map (0.5 m texels, 128 m around the camera) of the highest object top above each texel and its coverage. Any placed object shelters the ground below its top, so trees, shrubs and rocks need no tagging: streamed objects carry an `ObjectFootprint` from their largest LOD bounds, and the [engine](../crates/engine/src/weather.rs) rebuilds the map while rain or wetness needs it, after moving 16 m, on origin rebases and (throttled to 0.5 s) when objects stream. Materials bind it at 123 beside the cloud inputs; rain streaks, splash placement, surface wetness and puddles all use the same bilinear lookup. Splashes are spawned on the CPU on resident terrain in a disc around the ground the camera looks at, at constant density per square metre (skipping steep and sheltered ground), into a 512-entry ring buffer with the terrain normal. Each draws a ripple ring lying on the surface (strong on wet ground, faint on dry) and four droplets thrown in a cone that fall back under gravity, hidden behind nearer geometry such as grass. [Puddles](../assets/shaders/weather/ground_wetness.wgsl) follow the relief: the cooker stores each ground composite texel's hollowness (depth below the ground within 1.5 m, saturating at 15 cm; averaged into coarser pages) in the colour alpha, which was always opaque. As ground soaks, water rises into road ruts and dips deepest first; when soaked, hollows about 4 cm deep hold water, and a few sparse noise puddles remain on open flat ground. Only wet ground within 80 m reads the value: one extra texture read, plus a detail-tile lookup where the close surface cache supplies colour. Composite version 1 pages decode with no hollowness until re-cooked, and the legacy terrain path uses noise puddles. Ripple rings animate while rain falls; only the terrain shaders call it.

Game defaults are 50% of physical width/height, 4× MSAA, native-resolution UI, Auto upscaling, Balanced grass/clouds and optional counters off. Auto uses MetalFX Spatial when supported, otherwise Linear. Explicit Linear samples the scene directly during UI composition. MetalFX Temporal is an integrated, selectable game backend: it replaces MSAA, requires mesh depth/motion, writes grass color/motion/final depth, reconstructs HDR before full-size postprocessing, and resets history on discontinuities. Motion excludes jitter; exposed HDR uses a unit exposure hint. Recorded performance and moving-grass quality issues remain unresolved; these are follow-up issues in an implemented feature, not missing temporal integration. See the ledger.

`MsaaColorStorePolicy::Automatic` discards multisample color only when later consumers permit it; depth is retained. New passes loading that color must request Preserve or extend the consumer check. Atmosphere views qualify only while `BevySkyPassReplaced` confirms Bevy's sky pass is gone. This adapts Bevy's opaque schedule, as the sky composite adapts its sky pass; both must be rechecked on upgrades. The [wgpu-hal patch](../third_party/wgpu-hal/YARRA_PATCH.md) supplies the Metal minimum presentation interval for frame pacing; it is not obsolete vendored experimentation.
