# Experiment ledger

Decisions and observations through 2026-09-21. Current behavior belongs in [architecture](ARCHITECTURE.md); reproduction and measurement rules belong in [performance](PERFORMANCE.md). This ledger replaces the individual experiment reports. **Retained means present/useful, not necessarily a proven frame-time or energy improvement.** Rejected trials should not be revived without a new hypothesis.

Most desktop measurements used M2 Max; early phone work used iPhone 15 Pro Max / A17 Pro. Scenes, pixels, density, clocks and measurement methods changed. Compare only matched runs within an entry. A counter reduction, Xcode replay duration, sampled GPU span, Metal HUD duration and delivered frame interval are different measurements. Temporal GPU markers are known to undercount. No result here establishes mainstream-PC 1440p/60 acceptance or sustained phone 60 FPS.

**Density correction:** September 15–16 default-fixture captures labelled “44 roots/m²” actually used **66**. The cooked catalog is authoritative. Historical 32 m grass fixtures are different from the current 8 m authored world. Later 96/128-density fixtures are explicit variants. Old report labels inside raw archives remain historical; use this correction when interpreting them.

## Tree LOD material publication — September 23

**Retained correctness fix.** The native offscreen forest-tree test, using the debug test build on macOS/Metal with Temporal disabled, reproduced missing foliage on the first frame of all eight switches through four imported Tree 07 LODs; bark remained drawable. Wind material conversion ran after `AssetEventSystems` because it waited for calculated bounds. Cloud/wind material conversion now finishes before asset events and render specialization; bounds expand separately before culling. The same eight transitions now have no material/color-pipeline gaps, including the final test's depth/motion-prepass readiness checks. [Before](performance/20260923-tree-lod/before.log), [after](performance/20260923-tree-lod/after.log), [regression](../crates/engine/src/tree_wind/scene_tests.rs). This isolates the canopy-dropout defect; the preceding whole-view Temporal roughness and reported frame-time spikes are not proven to share that cause. Every history/target reset can now be logged with `--metalfx-timing-log`; no AA quality, LOD thresholds or reset policy changed. No performance gain claimed.

## Grass residency and temporal history — September 23

**Retained correctness fix; user confirmed the gameplay flicker is resolved.** After the tree-material fix, the user isolated the continuing whole-view flicker to grass: it persisted with terrain/objects/clouds disabled and stopped with grass disabled. A native offscreen MetalFX test on M2 Max (optimized debug test build, 128×128 input / 256×256 output) then reproduced 24 whole-view history resets in 24 offscreen page additions/removals. Resident-page repacking was treated as a global history cut. Catalog revisions are now tracked separately: residency and grass visibility changes retain history, while catalog edits, explicit camera cuts and origin/time discontinuities retain invalidation. Current stable roots/seeds rebuild previous blade poses when packed indices change. Queueing also no longer uses the previous frame's active flag, which caused a missing first grass draw after an empty scene or re-enable.

The same 24 updates now produce **zero history resets**, across prepared and procedural geometry, stationary cameras, strafing and wind. Empty/populated and disabled/enabled transitions retain history and draw immediately; camera-only motion agrees with depth reprojection to p95 <0.001 input pixel. Explicit camera cuts and catalog edits still reset. [Before](performance/20260923-grass-temporal-streaming/before.log), [after](performance/20260923-grass-temporal-streaming/after.log), [regression](../crates/vegetation_render/src/renderer/blade_preparation/temporal_streaming_tests.rs). No whole-game performance gain measured: native reset sets a scaler flag rather than reallocating it; page uploads/cache rebuilding and previous-pose work remain. Earlier Temporal cost/strafe-blur findings remain open. `--metalfx-timing-log` now additionally records grass source changes and reset reasons as `GRASS_TEMPORAL_HISTORY`.

## Game weather — September 25

**Retained first milestone; appearance not yet accepted.** Weather presets, random sequence, F1 controls, shared wind and weather fog as described in [architecture](ARCHITECTURE.md#atmosphere-and-presentation). Release M2 Max, `grass-close` repro, Spatial, 4× MSAA, snapshots at frame 600 ([presets](performance/20260925-weather/presets.jpg): clear, overcast, rain, storm).

| Change | Decision / observation |
| --- | --- |
| Weather visibility through Bevy's aerosol medium | **Rejected.** Storm (1.6 km) and faintly Rain (4 km) produced coloured one-pixel horizontal streaks that persisted with Linear upscaling and with clouds off. Bevy's `sample_transmittance_lut_segment` divides two half-float transmittances that underflow for ground-hitting rays through dense haze; 0/0 becomes NaN, which bloom spreads. Haze in that model is also sun-lit under a full cloud deck, which washed out overcast scenes. | Weather fog in the cloud composite | **Retained.** Adds only the extinction missing from the authored haze; clear weather keeps the previous early exit below the horizon. Averaged transmittance over resolved MSAA colour left bright halos where silhouettes met the horizon sky; edges touching the sky now take the sky's transmittance (at most one pixel of lost edge smoothing, no effect without MSAA). Cost unmeasured. |
| Sky cache invalidation | **Changed.** Continuous weather values no longer invalidate the cache (previously a full 512² trace every frame of a transition). Refresh is now a per-frame row budget instead of quarter-atlas stripes every ~31 ms; same eight complete refreshes per second. Unit-tested, not timed. |
| Wind during weather changes | **Retained.** `VegetationWind::rate` scales the phase clock (clamped so one frame stays below the grass history-reset threshold); changing `speed` would jump every wave. |
| Close-up lighting under cloud (user report, Temporal) | **Changed.** Near tree trunks looked fogged next to dark grass; fog is ~0.4% at 3–5 m, so it was lighting. Bevy's ambient term is a large share of clear-day light, and −1.5…−2.5 EV offsets made ambient-lit PBR surfaces brighter than sunlit ones, while grass bounds ambient at 0.60 exposed and stayed dark. Blue clear-sky ambient on pale bark matched the fog tint. Now: offsets −0.8/−1.0/−0.9 EV, weather greys skylight colour, grass ambient bound scales with exposure adaptation only (a linear on-screen ambient gain made grass brighter than sunlit grass), and sun shadows no longer darken grass ambient where clouds block the sun. Eye-checked only. |
| Cloud sky "lines" (user report, predates weather) | **Changed.** Distant clouds showed a regular diagonal sawtooth. Cause: the 512² stereographic cache maps the horizon to a circle, so 1–2-texel cloud slivers crossed the square texel grid diagonally and bilinear filtering showed the grid. Per-texel ray jitter with refresh accumulation was tried first and **rejected**: no visible change, so ray-march slicing was not the cause. Replaced by a 2048×256 horizon-aligned panorama at 4 Hz (same rays per second as 512² at 8 Hz; ~5.7 vs ~4.2 texels per degree of azimuth, about double the elevation resolution near the horizon). An intermediate 1024×256 removed the staircases but blurred clouds horizontally. Azimuth seam checked by rotating it into view. [Before/after](performance/20260925-weather/sky-cache-before-after.jpg). Post-hitch refresh bound kept at 65,536 rays. Eye-checked, not timed. |
| Visible cloud "morphing" during weather changes | **Changed.** Two causes: every texel updated only four times per second with a refresh cursor sweeping the sky, and one global coverage threshold grew or shrank all clouds at once. The cache now keeps three images and the composite cross-fades the two latest complete refreshes (+8 MiB, one extra texture sample per sky pixel, unchanged tracing); cloud shape blends region by region from a noise arrival field already sampled by the density function. F1 blends default to 60 s again. A temporary Clear→Storm 10 s capture showed patches forming before the deck closes. Smoothness in motion and cost are not measured. |
| Sky composite replacing Bevy's sky pass | **Retained.** One pass on the resolved image for sky, aerial perspective, clouds and weather fog, classifying every depth sample. Release M2 Max, 2560×1440, 4× MSAA, frame-600 snapshots against the previous build: clear `ground-low` mean difference 0.01/255 including sky and horizon; overhead overcast ≤1/255; storm and rain views differ only in random rain streaks; Temporal `grass-close` (75%, no MSAA) likewise. A temporary log confirmed the opaque pass now discards multisample colour in normal play; before, Bevy's sky pass kept it stored every frame, so GP003 never applied with the atmosphere on. Short `grass-close` clear runs, unfocused window, sampled GPU frame time, before/after/before/after: medians 5.68 / 5.43 / 5.85 / 5.67 ms (about 0.2 ms; 12–13 samples each, not a controlled profile). Hiding the sky (F1) used to remove Bevy's atmosphere, and with it the depth sampling usage the cloud composite bound: the likely cause of the earlier black frame. The switch now keeps the tables and views request sampled depth themselves; forcing it off through a temporary hook rendered the scene with a black sky, clouds and weather fog intact. |
| Relief-aware puddles | **Retained.** Puddles came from noise alone, so water ignored the road's carved ruts. Runtime options were sampling heights around each pixel (several reads per wet pixel) or a cook-time value; the cooker now bakes hollowness into the composite colour alpha, so wet pixels within 80 m pay one texture read (plus a detail-tile lookup under the close surface cache). ## Frame cost attribution — September 26

M2 Max, release, `--weather clear`, 4× MSAA. User report: with nearly everything off in F1 at native 3456×1942 the Metal HUD still showed ~5 ms GPU (terrain on) and ~3.5–4 ms (terrain off). Metal System Trace (`xctrace` attached after a 20 s warmup) showed the GPU in its **Minimum** performance state for most of the terrain-off recording and **Maximum** with terrain on: the same passes took about twice as long in the lighter scene (tone mapping 0.15→0.28 ms, UI 0.19→0.44 ms, atmosphere tables 0.60→1.35 ms). HUD GPU time under light load is therefore inflated by clock scaling and is not a work measure. At maximum clock the terrain-only frame was dominated by the opaque pass (2.96 ms), the sky composite (0.52 ms), atmosphere tables (0.6 ms), the unused depth prepass plus Bevy's depth copy (~0.5 ms) and native-resolution tone mapping/upscaling/UI copies (~0.75 ms). Per-encoder intervals overlap (compute runs beside shadow rendering), so they rank work but do not give marginal costs.

Marginal costs below come from uncapped timed profiles (`--profile-fps 0`, GPU-bound, 2560×1440 native, everything on, prepass off, 10 s after 8 s warmup), interleaved and repeated; ±0.3 ms is noise from clock and thermal drift.

| Change | Decision / observation |
| --- | --- |
| Depth prepass off outside Temporal | **Retained/default.** 9.46/9.31 → 8.63/8.72 ms on the grass route. Facing the forest at native 3456×1942 (uncapped profile, sampled GPU time) it cost ~1.0 ms: 11.23 → 10.25 ms; see the forest row below. Alpha-tested leaves were drawn in both passes. An earlier estimate from trace frame counts (trees 3.8 ms with it, 1.6 ms without) was noise and is superseded. Only MetalFX Temporal consumes it, and the game still adds it there. A repro snapshot with and without it differs by at most 1/255. |
| Shadows | **Open, user decision; F1 Features → Shadow map compares 2048/1536/1024.** Off saves ~2.2 ms. 1024² maps save ~0.7 ms, 1536² ~0.15 ms, terrain not casting ~0.2 ms; Gaussian vs 2×2 filtering makes no difference. With every mesh a non-caster (maps still rendered and sampled), about 70% of the cost disappeared: casting dominates, and the lookup while shading is 0.4–0.9 ms. A 1024² close-up looked only slightly softer. |
| Coarse tree shadow casters | **Rejected before implementation.** On the grass route, forcing coarser tree LODs everywhere (LOD scale 0.25) left the shadow cost unchanged (~1.9 ms either way), so shadow-only low-LOD proxies would not help there; covered map area and per-cascade work dominate. |
| Facing the forest (user report: 11.62 vs 7.08 ms HUD facing towards/away) | Reproduced with the `grass-close` pose turned 45° to face the forest, uncapped native 3456×1942 profile, 4× MSAA, mean sampled GPU time: prepass on 11.23 ms (the user's HUD case), off 10.25/10.23 ms. | Terrain shader components | Disabling parts in the shader: close-range surface 0.7–1.25 ms, lighting including normal/roughness work 1.3–2.0 ms, directional shadow lookup 0.4–0.9 ms, canopy noise ~0.14 ms; macro variation, detail tiles, decals, cloud shadow lookup and the BRDF itself were within noise. | Forest cost anatomy (tree assets) | Leaf cards are 35–37% opaque on trees and 22–33% on shrubs (texture alpha ≥ 0.5 sampled over each triangle, weighted by world area); the shared leaf atlas holds sparse branch sprites (21% opaque overall), and crowns stack 2–3 layers of cards. | Near vs far trees | Same view, trees beyond a distance hidden: all 10.7–11.2 ms, within 50 m 8.6–8.7 ms, within 30 m 6.8–7.1 ms, none 6.3–6.9 ms. ~85–90% of the tree cost comes from trees beyond 30 m (about half beyond 50 m); impostors from ~30–40 m address most of it. |

| Terrain / trees and objects / bloom / sky and haze | Hiding them saved ~1.7 / ~1.2 / ~0.9 / ~0.4 ms. Tree cost includes their shadow casting. |
| Grass / clouds | Grass 0.7–1.0 ms (9.1–9.2 → 8.2–8.4 ms with `--profile-grass off`); clouds ~0.1 ms. A first grass figure of ~0.2 ms and early bloom figures came from switching F1 settings inside a profile, which re-applies its own grass and bloom presentation; use the profile flags for those. |
| Atmosphere tables | Near-free table settings changed nothing measurable: the compute runs beside shadow rendering. Caching the static tables is not worth owning Bevy's table pass. |

## World storage — September 26

Question: how much cooked data a world needs per km². The authored 8 m world measured ~1.3 GB/km², far too much for a ~40 km² island. Main fixture: `create-hill-fixture` (48×48 cells of 32 m, 2.36 km², 1 m heights, Y −8..350 m). Every run cooked the same source once, on M2 Max with a release build and material bake. [Summary](performance/20260926-world-storage/summary.json).

| Change | Decision / observation |
| --- | --- |
| Where the bytes went | Per 8 m authored cell: 16 KB terrain page (f32 heights, 16-bit normals, 12.5 cm weights), 7.5 KB grass fields, 8 KB leaf node repeating the page's heights and normals, and a 38 KB composite (12.5 cm texels), plus about a third again for parent levels. Composites were ~60%; float heights barely compress under zstd. |
| Compact heightfields | **Retained.** Heights on a world-wide 1/1024 m grid, 12-bit octahedral normals, planar-predicted varint steps. Hill: terrain pages 21.0 → 9.0 MB, nodes 24.2 → 9.7 MB, file 155.5 → 130.1 MB (66 → 55 MB/km²); cook 69.7 → 70.0 s. Authored world: pages 4.2 → 2.8 MB, nodes 2.7 → 0.9 MB. The previous contract kept source f32 heights so shallow road relief survives on mountains, where a 16-bit range per page would round it to centimetres; the global grid keeps millimetres at any altitude and keeps shared edges identical. |
| Composite minimum level | **Retained, per world, default 0 (unchanged output).** Hill level 1: 3064 → 760 tiles, composites 93.4 → 25.4 MB, file 57.7 MB (24 MB/km²). Level 2: 184 tiles, 6.6 MB, file 38.2 MB (16 MB/km²); cook 61 s. Coarser tiles are byte-identical to a full cook (test). Authored world at level 2: 21.8 → 6.4 MB of payload (~0.39 GB/km²), now dominated by 12.5 cm weights and grass fields. Native release renders of the hill `valley` and `summit` bookmarks (`landscape` repro, frame 900, 2560×1440; summit also with `--weather clear`) differ from level 0 by 0.08–0.15/255 on average. At most 0.2% of pixels differ by more than 8/255, mostly the animated character. There, grass and haze cover the ground beyond the 40 m near range. Bare rock, sand or roads at 40–150 m will show the coarser texels until composites are generated at runtime. |
| SQLite layout | **Open.** About 10 MB of the 38 MB level-2 hill file is row overhead: 3–4 KB blobs spill to overflow pages. No page size from 4 to 64 KiB wins for both runs; rowid tables recover only ~3 MB. Packing several cells per row is the likely fix. |
| Remaining duplication | **Open.** Leaf heights and normals are still stored in both the cell page and the level-0 node (~3 KB per 32 m cell each). Legacy terrain, CPU sources and editor previews read the page copy. |

| Change | Decision / observation |

| View distance | **Retained.** Bevy's default 1 km far plane had culled all distant terrain. World views now cull at 20 km. Terrain cost stays bounded by the screen-error LOD. The massif reads clearly through haze from 3 km. |

The cache now holds every baked level: 572 MB. The remaining ~5 s is fixed per publication: cloning, re-sealing roots and hashing all node and tile checksums. |
| Frame rate | Uncapped `landscape` profiles, 2560×1440 native, 4× MSAA, grass on: island 93–99 fps (update p95 ~21–22 ms), hill fixture in the same build 137–152 fps (p95 ~14 ms). Update intervals, not GPU attribution; the high p95 also occurs on the hill. |

| Change | Decision / observation |

## Open gates and maintenance

The remaining gates are sustained terrain/whole-game power, Temporal cost and motion quality, field-scale grass lighting, target-PC acceptance, and physical-phone heat/60-FPS delivery. Keep correctness references until their replacements pass the relevant gate. Existing counters often identify less work without demonstrating better delivered frames or lower power.

For each new experiment update one row or add a compact entry: date/ID, hypothesis, retained/rejected/unresolved decision, device/build and workload, before/after metric, limitation, evidence link. Do not create another standalone report. Raw evidence lives under `performance/`; prose removed during consolidation remains in Git at `2afce93`. New architecture proposals and cleanup work belong in [refactoring](REFACTORING.md), not this results ledger.
