## Gameplay implementation roadmap

Quest-aware conversations now include role-bound lines, repeat policy, scoped history and durable reward claims. Indexed immutable content now supplies bounded sessions backed by private SQLite working state. Modular authoring and localization are implemented. Scripting and world/editor integration remain the target design in [Architecture](ARCHITECTURE.md#scalable-dialogue-and-localization-design).

Work in dependency order, with small runnable batches inside each milestone. Replace superseded gameplay schemas directly, regenerate authored fixtures and reject old formats explicitly; do not add backward-compatibility adapters. Preserve transaction guarantees and ordinary world/editor behavior. Use existing crates where ownership fits, splitting a crate only for a real dependency boundary. Keep game integration opt-in while the standalone API is under construction.

### Completed: bounded sessions, saves and headless driver

`GameSession` now depends on state/content ports; `WorkingStore` resolves indexed mutable records and `ContentRepository` resolves only the operation's immutable dependencies. Commands clone/validate the bounded working set and commit record revisions, item ownership, facts, RNG and the header together. Expiration processing uses an explicitly selected deadline index and bounded actor batches, preserving intermediate health caps across large time steps. Item identities created by commands are reproducible after restore. The obsolete full-state session accessors and inventory-state persistence adapter are removed.

Save/working schema 3 stores no definitions. Online SQLite backup copies a pinned snapshot in page batches; staging and atomic publication preserve previous slots on failure. Restore creates a new private working file and opens metadata only. `ContentLibrary` retains mechanical generations independently of slots and resolves them before restore. `HeadlessDriver` shares commands/queries, fixed logical time, bounded predicates and event traces. The demo now exercises the indexed runtime and retains content next to its saves.

### Completed: modular authoring and localization

Source/bundle formats 3 replace the fixed layout and global Fluent namespace. Packages own catalog fragments, actor collections, rules and conversation assets with explicit dependencies. Each conversation has a graph, local condition/action bindings, text contracts and co-located Fluent resources. Stable identities and canonical ordering make directory moves/package reordering harmless. `BindingId` scopes action/condition names to a dialogue UUID. `TextRef` scopes local message IDs to a resource UUID.

Mechanical bundles contain typed text contracts, not wording. Language-pack format 1 independently publishes indexed, checksummed locale resources. Runtime formatting fetches only requested scopes/imports and locale candidates, with bounded caches and pinned handles. Publication walks Fluent branches/dependencies and validates typed arguments/selectors, attributes, terms and cycles. Whole-message fallback avoids mixed-language terms. Dependency hashes track translation reviews; shipping locales require reviewed completeness. Unsupported Fluent functions and positional term arguments fail explicitly.

This milestone introduced save/working and inventory-authoring schemas 4 because scoped text references changed persisted contracts. Old formats are rejected rather than migrated. Wording-only releases remain compatible with saves on the new schema. Tests cover independent language updates against retained mechanical content/saves, duplicate local text/binding names, directory moves, package ordering/dependencies, typed branches, fallback, review invalidation, lazy indexed language reads, cache pinning and failed publication preservation. All 84 standalone tests pass; strict all-targets clippy, formatting, diff and local documentation-link checks pass. Existing bounded gameplay/save and CLI publication/demo roundtrips remain regression gates. Game/editor integration is still opt-in and has not been wired in this batch.

### Session and checkpoint decision

The implemented private SQLite working store persists accepted changes so unloaded records remain recoverable; no persistent decoded-state cache is needed. Named manual/quick/auto slots advance only when the corresponding save operation occurs. Working persistence is not a change to the chosen save-slot UX. A checkpoint must include a coherent generation of resident/nonresident mutable records, RNG, claims and pending work. Content retention covers every referenced mechanical generation; missing required content is an explicit load error. Test discarding current unsaved progress and restoring an older slot as well as saving.
